# Review: pr-watch 2026-07-25 — PRs 35796, 35795, 35794

**CORRECTION 2026-07-25: the 35796 "build break" finding below was WRONG and is retracted.**

My analysis assumed the capnproto tarball has the repo layout (`c++/` at top level). It does not:
the release tarball (`capnproto-c++-1.5.0.tar.gz` from capnproto.org) is FLATTENED — the repo's
`c++/` directory becomes the tarball root, so the file lives at `src/kj/async-io-unix.c++`.
Verified by downloading the actual tarball and dry-running the PR's patch:

    $ patch -p1 --dry-run < macos_accept_dead_socket.patch
    can't find file to patch at input line 18
    1 out of 1 hunk ignored                      (exit=1)

    $ patch -p2 --dry-run < macos_accept_dead_socket.patch
    checking file src/kj/async-io-unix.c++       (exit=0)

So `-p2` is correct and REQUIRED for this package; `-p1` is what would actually fail.
The depends convention of `-p1` holds for packages whose tarballs keep the repo layout;
capnp's flattened tarball is the exception, and the PR author had it right.

Root cause of my error: I checked the patch header paths and the depends convention but never
verified the tarball's actual directory structure — exactly the verification I demand of others.
