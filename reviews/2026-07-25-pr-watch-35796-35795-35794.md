# Review: pr-watch 2026-07-25 — PRs 35796, 35795, 35794

## PR 35796 (depends: fix IPC listeners on macOS dying when accepting a dead socket) — 🟠 MERGE-BLOCKER

The fix content is fine (vendored upstream capnproto 7df5bd078 patch, tolerates EINVAL from setsockopt(TCP_NODELAY) on a dead accepted Unix socket on macOS). But the depends integration is broken:

**`patch -p2` must be `patch -p1`** (`depends/packages/capnp.mk`, preprocess_cmds).

- The patch file's paths are `a/c++/src/kj/async-io-unix.c++` (capnproto repo layout has `c++/` at the top).
- The depends build runs preprocess in the tarball root (`capnproto-c++-X.Y.Z/`), where the real file is `c++/src/kj/async-io-unix.c++`.
- `patch -p1` strips `a/` → `c++/src/...` (exists). `patch -p2` strips `a/c++/` → `src/kj/...` (**does not exist**).
- Result: the preprocess step fails → capnp depends build breaks on ALL platforms, not just macOS. Every other depends patch uses `patch -p1` (fontconfig, freetype, libxcb, native_qt…).

Trigger: any depends build (guix or local) with the patch applied — `patch` errors out on the missing file.
