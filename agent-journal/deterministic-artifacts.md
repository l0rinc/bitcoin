### Scope and Hypothesis

Cycle 9 already closed the Silent Payments generator and is excluded. This cycle selected the distinct `contrib/devtools/headerssync-params.py` pipeline and its generated `src/kernel/chainparams.cpp` parameter blocks. The hypothesis was that the documented invocation, `pypy3 contrib/devtools/headerssync-params.py`, did not produce a reproducible transcript or copied C++ block because it used an uncontrolled random search order and `datetime.today()` in generated output.

The trust boundary is the developer generator, its stdout block copied into the four chain-parameter constructors, and the `HeadersSyncState` consumer that reads `.commitment_period` and `.redownload_buffer_size`. The intended numeric parameters must remain unchanged; only the regeneration representation and search trace should become stable.

### Evidence Before the Fix

- `contrib/devtools/README.md` documents the generator invocation but specifies no random seed, environment contract, or timestamp policy.
- `headerssync-params.py` selected each candidate period with `random.randrange(len(periods))` and emitted `datetime.today()` in the copied C++ comment. The date was not an input to the optimization and changed only provenance text.
- Two clean runs on the same source, Python 3.11, and host produced different complete outputs:

  ```text
  run1: b8be97dd5c41b865608342383806ef5e0cf5c3bf14be7896cf32b43bcf6264f1  (789 bytes)
  run2: 7877c61f076c283fe4f17c580d490462fe8cc8a55c4654da7f027d11b034dde3  (843 bytes)
  ```

  The first run reported only the initial configuration and final improvement; the second reported two intermediate improvements. Both ended with the same numeric result, `commitment_period = 641` and `redownload_buffer_size = 15218`, but both emitted `Generated by headerssync-params.py on 2026-07-30`, while the checked-in artifact still said `on 2026-02-25`.
- The changing search transcript demonstrates uncontrolled output nondeterminism, and the wall-clock comment makes the generated source differ whenever the tool is rerun on another day. Neither difference changes runtime behavior, but both violate the artifact regeneration contract and create unnecessary review/build noise.
- History traces the timestamped output to `cc5dda1de333cf7aa10e2237ee2c9221f705dbd9` (`headerssync: Make HeadersSyncState more flexible and move constants`) and shows the current generated comments updated by `58c2e23fca05d201dfcea092ab032c943c9d566` (`kernel: Update headerssync params`). No deterministic seed or timestamp override was added later.

### Fix

- Seed the generator's optimization search with `random.seed(0)` immediately before `analyze(TIME)`, preserving the selected numeric result while making the search trace repeatable.
- Replace the wall-clock comment with the stable `// Generated by headerssync-params.py.` text.
- Update the four corresponding generated comments in `src/kernel/chainparams.cpp` for mainnet, testnet3, testnet4, and signet. The four numeric parameter pairs are unchanged.

### Verification

```

The generated mainnet C++ block compares byte-for-byte with lines 223-227 of the checked-in `chainparams.cpp`. `python3 -m py_compile contrib/devtools/headerssync-params.py` passed. A fresh Clang 19 UBSan/alignment/object-size build of `test_bitcoin` completed all 198 build steps, and:

```

`git diff --check` passed. The source change does not alter the generated numeric parameters or the runtime headers-sync algorithm.

### Verdict and Handoff

**Confirmed generated-artifact nondeterminism; fixed.** The generator previously depended on ambient PRNG state and wall-clock date, so the documented regeneration path could not reproduce its own output text. The smallest fix controls the search seed and removes non-semantic date text, while preserving all runtime values. The source/test/journal finding commit must include this record; the next separate commit will close the uber-goal state.

### Limitations

- No release, alternate architecture, locale-specific Python, PyPy, or cross-version interpreter run was available. The exact repeated Python 3.11 output and source/build validation are the current evidence.

## Cycle 306: Generated C comment injection in vector regeneration

### Cycle identity

### Scope and hypothesis

Earlier Goal 39 cycles covered Silent Payments regeneration, headersync's
random search and timestamp, and MuSig2 invocation-path output. This cycle
selected the remaining Wycheproof and Silent Payments generator boundary. A
caller-selected JSON corpus is redirected into a C header and compiled into
libsecp256k1 tests. The hypothesis was that a vector `comment` containing the
C block-comment terminator could escape the generated comment and alter or
break the test source.

The sinks were `src/secp256k1/tools/tests_wycheproof_generate_ecdsa.py:79`,
`tests_wycheproof_generate_ecdh.py:133`, and
`tests_silentpayments_generate.py:255`. Local secp256k1 security evidence had
preserved this as an unverified generated-C injection candidate; no source fix
was present.

### Failing-before evidence

`agent-journal/cycle306_generator_probe.py` constructed minimal ECDSA and ECDH
fixtures and copied the checked-in BIP352 corpus for a Silent Payments fixture.
Each first vector comment was replaced with:

```text
*/
int generated_marker = 1;
/*
```

Before the fix, all three generators emitted the marker as live source inside
the generated test-vector initializer. Each header failed
`cc -std=c11 -fsyntax-only` with `error: expected expression before 'int'` at
the injected line:

```text
ecdsa: marker=True compile=1
ecdh: marker=True compile=1
silent: marker=True compile=1
```

This is a source-integrity failure at the developer/build boundary. A
compromised or otherwise untrusted vector refresh could alter or execute test
source on the host. The trusted corpora themselves regenerated byte-for-byte
before the change:

```text
ecdsa 1e3c11ff4c5c83cbd0d79b3ede6a47309e2074f0f9432f3aef09e3bb2c9004c5
ecdh  040085b0859e4cc41105bfecec825c76c616fe89a703f8221807c6433ba9f3d2
silent 8d88aead1f2f359aca31ac8c803001c55b1231be187839cafbe9c6959cedbbcc
```

### Fix

Added `sanitize_c_comment()` to `tools/wycheproof_utils.py`, replacing every
`*/` in external text with `* /`. Both Wycheproof generators and the Silent
Payments generator now use it at every external-comment emission. The helper
was also added to `Makefile.am`'s `EXTRA_DIST`; the Wycheproof scripts already
depended on this sibling module, and Silent Payments now shares the same
safety contract.

### Verification

The same hostile fixtures after the fix compiled successfully, retaining the
marker only as comment text:

```text
ecdsa: marker=True compile=0
ecdh: marker=True compile=0
silent: marker=True compile=0
```

The three production regenerations remained byte-identical to their tracked
headers after the fix, with the same hashes above. `python3 -m py_compile`
passed for all four changed Python files, and `git diff --check` passed.

Consumer coverage passed with fixed seeds in both available release builds:

- Clang 19: ECDSA and Silent Payments modules passed, including
  `ecdsa_wycheproof` and `run_silentpayments_test_vectors`.
- GCC: the same ECDSA and Silent Payments modules passed.
- A fresh Clang 14 Release CMake build with ECDH enabled compiled the current
  generated header and passed all ECDH tests, including
  `test_ecdh_wycheproof` (7 tests, 0.076 seconds).

### Verdict and handoff

**Confirmed and fixed.** External vector comments could terminate generated C
comments and inject source into the test header. The replacement is the
smallest behavior-preserving hardening: trusted current comments and generated
bytes do not change, while hostile comment text remains non-executable. The
source fix and this journal entry belong in one self-contained commit.

### Limitations and next queue

- The hostile fixture proves source break-out and post-fix compilation, but is
  scratch-only; the repository has no existing Python generator test target.
- This cycle did not audit generated manpages under all `help2man`/locale
  versions, Sage/minisketch precomputation output, or seed selection

- Recheck those distinct cells in future Goal 39 cycles and extend the
